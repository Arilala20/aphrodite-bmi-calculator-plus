# BMI Calculator Plus testing guide

This project uses Node.js's built-in test runner. No third-party packages or browser automation dependencies are required for the unit suite.

## Requirements

- Node.js 18 or newer, which includes the stable `node:test` runner.
- npm, included with Node.js, if using the package script.
- A modern browser to perform the optional manual/browser smoke test.

There is no dependency installation step. The project remains a static HTML/CSS/JavaScript application.

## Run the complete automated suite

Run from the project directory (`aphrodite-bmi-calculator-plus`):

```sh
npm test
```

Or run the test file directly:

```sh
node --test tests/script.test.js
```

Node discovers the test file through the `node --test` command. Tests use an isolated VM context, a deterministic clock, a small fake DOM, and in-memory local storage. They execute the production `script.js` without requiring a browser.

## Smoke tests

The automated suite includes an HTML wiring smoke test. It checks for essential form/result/history IDs, references to `styles.css` and `script.js`, and accessible names for the Imperial height fields:

```sh
node --test --test-name-pattern="HTML smoke check" tests/script.test.js
```

For a real-browser smoke test:

1. Open `index.html` in a modern browser.
2. Confirm the page title, calculator form, BMI result card, and empty history are visible.
3. Submit the default metric values. Confirm BMI `22.5`, category `Healthy range`, and one saved history item.
4. Switch to Imperial. Enter `5` ft, `7` in, and `143` lb; submit and confirm BMI `22.4` and a second history item.
5. Select **Reset values** and confirm that the result clears and metric defaults return.
6. Select **Clear history** and confirm the list empties and the clear control becomes disabled.
7. Check the browser console for runtime errors.

The browser smoke test is a manual procedure and is not part of `npm test`. A Playwright/browser smoke test was also run during this assignment session; its measured outcome is recorded in the task report, not generated by the Node suite.

## What the automated tests cover

`tests/script.test.js` drives production UI handlers and asserts user-visible output and side effects. It covers:

- Startup state and required HTML references.
- Metric and Imperial calculations, conversion, decimal rounding, allowed input ranges, and BMI category boundaries (`18.5`, `25`, and `30`) in both unit systems.
- Very low/high accepted results and BMI marker clamping.
- Missing/blank, null-like, undefined-like, whitespace, negative, zero, out-of-range, malformed, and very long field values across metric and Imperial controls.
- NaN, positive and negative Infinity, very large finite numbers, null-like and non-string values.
- Unicode rejection in numeric fields, including Chinese, Arabic, accented Latin characters, emoji, and mixed text.
- Optional age, age bounds, under-20 guidance, unit switching, reset, repeated interactions, mobile result focus/scroll behavior, and reduced-motion behavior.
- History serialization, rendering, eight-entry limit, malformed JSON/structures, missing and wrong-type properties, invalid dates, non-positive/non-finite BMI values, and local-storage read/write/remove failures.
- Regression behavior: failed calculations preserve the prior result/history; reset preserves saved history; corrupted persisted entries are excluded safely.

Input values such as Unicode text, Infinity, and long strings are expected to be rejected by the numeric form validation; the tests verify safe rejection rather than accepting them.

## Documented production functions

The implementation is a self-invoking browser script, not an exported module. These functions are private to that closure. Their JSDoc is maintained next to each declaration in `script.js`.

| Function | Parameters | Return | Purpose and observable effects |
| --- | --- | --- | --- |
| `category(bmi)` | Numeric BMI | Category key | Maps adult BMI thresholds to `under`, `healthy`, `over`, or `obese`. |
| `readHistory()` | None | Validated history array | Reads `aphrodite-bmi-history` from `localStorage`, filters invalid records, and reports read/parse failures in the status element. |
| `renderHistory()` | None | `void` | Updates history rows, saved count, empty state, and clear-button disabled state. |
| `setError(message, invalidFields)` | Message; optional input IDs | `void` | Updates the alert and `aria-invalid` fields, then focuses the first invalid field. |
| `saveHistory()` | None | `void` | Saves in-memory history and reports storage write errors while preserving the calculated result. |
| `calculate(event)` | Optional submit event | `void` | Validates inputs, converts units, calculates and displays BMI/category/guidance/marker, persists history, and navigates to the result on mobile. |

Arrow-function callbacks register and handle unit-switch, input, reset, and history-clear interactions.

## Documentation conventions

JavaScript uses JSDoc for function signatures, parameter types, return types, and concise behavior descriptions. This is analogous in purpose to Python docstrings described by PEP 287; PEP 8 itself is Python's style guide and does not define JavaScript documentation syntax. README and this guide document how to run and interpret the tests.

## Limitations

- The fake DOM is deliberately small. It verifies event-handler behavior and mutations the script uses, but it is not a substitute for a full browser accessibility tree or cross-browser rendering test.
- The HTML smoke check is static and cannot prove that every selector binds in a browser. Use the real-browser smoke procedure for integration.
- BMI calculations are tested against deterministic JavaScript arithmetic. The suite is not a medical validation of BMI guidance.
- No line or branch coverage percentage is reported. Since production source is evaluated in a VM from the test harness, Node's built-in coverage does not attribute that evaluated source to the production file reliably.
- Browser local storage is simulated in unit tests. Actual browser persistence depends on browser privacy settings and the page's execution context.
